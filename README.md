## ✨ 核心亮点：反幻觉四道防线

大模型最危险的错误是「一本正经地编造财务数字」。本项目**不依赖模型自觉**，而是用确定性校验兜底：

| 防线 | 做什么 | 效果 |
|---|---|---|
| **① 输入约束** | 只让模型看清洗后的「事实包」，不让它自由发挥 | 从源头减少编造 |
| **② 数字校验** | 报告里**每个**财务数字都被分级：命中指标词典的与事实库逐条比对；**没命中的也不会被放过，而是标为「无来源」** | 抓出编造的数字，并暴露"没被检查"的数字 |
| **③ 语义校验** | 检查有没有无来源的定性判断/因果归因 | 抓出无依据的判断 |
| **④ 逻辑审校 / 引用溯源** | 公司速览走三表勾稽；**深度研报走"引用溯源校验"——正文里的数字必须能在它引用的检索资料里找到** | 抓出逻辑错误与编造引用 |

### 数字校验到底覆盖多少？（v4 升级）

旧版只检查**命中 18 个指标词典**的数字，词典外的数字（研发投入、市占率、合同金额……）会被**静默放过**，
却看起来"已经校验过了"。v4 起改为**全量分类**：

| 状态 | 含义 |
|---|---|
| `supported` | 命中指标词典且与事实库一致 |
| `mismatch` | 命中指标词典但与事实库矛盾（疑似幻觉） |
| `unverifiable` | 命中词典但事实库没有该项数据 |
| **`unsourced`** | **未能归因到任何已知指标，也未在事实库中找到对应值 → 明确列出，需人工复核** |

同时输出：

- **`coverage`（可核实覆盖率）** = 一致数字 / 全部财务数字；
- **`unsourced_ratio`（无来源占比）**；
- **`contradictions`（报告内部自相矛盾）**：同一指标在文中出现多次且数值不一致时显式列出；
- **`confidence_reasons`（可信度下调原因）**：覆盖率过低、无来源数字过多、内部矛盾时会**自动降级**并在报告中写明原因。

> ⚠️ **适用范围说明**：事实库路径（②③④ 中的三表勾稽）完整生效在 **公司速览 / 公告提炼**（有明确标的公司）。
> **深度研报**是主题研究、没有标的公司事实库，因此走的是第 ④ 条里的**引用溯源校验**——
> 它同样有数字级约束："正文数字必须出现在其引用的检索资料里"，能抓出编造引用与对不上的数字。
> 报告结尾的「🛡️ 反幻觉总览」会如实标注每条检查是否真的执行过；未执行时可信度为「未评级」。

实际效果：模型把营收写成 182.30 亿（真实是 152.30 亿），校验器精确抓出并自动纠错；
文中若出现"研发投入 8.6 亿元"而事实包没有该项，会被列入「无来源数字」并拉低覆盖率与可信度。

## 🛡️ 反幻觉详细原理

大模型最危险的错误是「一本正经地编造财务数字」。本项目**不依赖模型自觉**，而是用四道防线兜底：

```
AKShare 真实数据 → 清洗 → 事实库 FactBase（唯一数字来源，输入侧锁定）
                          │
                          ▼
              大模型只能依据「事实包」生成草稿
                          │
                          ▼
   CrossVerifier 抽取草稿中的每个数字声明，逐条与事实库按容差比对
                          │
        ┌─────────────────┴─────────────────┐
        ▼                                   ▼
   一致 supported                    矛盾 mismatch（疑似幻觉）
        │                                   │
        ▼                                   ▼
     输出成稿            回填「正确值纠错清单」→ 模型重写 → 再校验
```

### 四道防线详解

| 防线 | 做什么 | 怎么做 |
|---|---|---|
| **① 输入约束** | 不让模型自由发挥 | 只把清洗后的「事实包」给模型，明确说「只能用这些数据」 |
| **② 数字校验** | 抓出编造的数字 | 全量抽取报告里的财务数字；命中词典的逐条与事实库比对（金额/价格容差 1%，百分比 0.1 个百分点）；**未命中的进入「无来源」清单并拉低覆盖率** |
| **③ 语义校验** | 抓出无来源的定性判断 | 让模型把文本拆成原子声明，逐条判断是否有事实包支撑（在线模式） |
| **④ 逻辑审校 / 引用溯源** | 抓出逻辑错误与编造引用 | 公司速览走三表勾稽 + 内部矛盾检测；**深度研报走引用溯源：正文数字必须出现在其引用的检索资料里** |

### 实际效果

模型把营收写成 182.30 亿（真实是 152.30 亿）、净利增速 15.20%（真实是 9.40%）、毛利率 50%（真实是 42.30%），校验器精确抓出三处矛盾并给出真实值：

```
交叉校验结论：未通过｜可信度：D（不可信）｜共核对 6 个数字：一致 3、矛盾 3、无法核实 0、无来源 0｜可核实覆盖率 50%｜疑似幻觉率 50.0%
  [✗] 归母净利润同比增速：文本称 15.20%，但经数据核算应为 9.40%，存在矛盾
  [✗] 销售毛利率：文本称 50.00%，但经数据核算应为 42.30%，存在矛盾
```

**无来源数字长这样**（事实包里没有该项，过去会被静默放过）：

```
**无来源数字（2 个，未能归因到事实库，需人工复核）：**

| 数字 | 上下文 | 说明 |
| --- | --- | --- |
| 8.60 亿元 | 报告期内研发投入8.60亿元 | 该数字未归因到任何已知指标，也未在事实库中找到对应值，无法核实（需人工复核） |
| 3.70% | 公司市占率3.70% | 该数字未归因到任何已知指标，也未在事实库中找到对应值，无法核实（需人工复核） |
```

> ⚠️ **边界说明（诚实版）**：
> - 「无来源」不等于幻觉，而是"系统无法核实"——可能确实来自公告或交流，也可能就是编的，因此**必须人工复核**；
> - 覆盖率分母是"财务数字"（金额/百分比/倍数/价格）；年份、股票代码、"5 家"这类纯计数不计入；
> - 事实库路径（②③ + 三表勾稽）仅在**公司速览 / 公告提炼**生效；深度研报用第 ④ 条的引用溯源校验。

## 🤖 多智能体流水线详解

深度研报（`report` 命令）不是一次性让大模型写完，而是分成 6 个阶段，每个阶段由专门的智能体负责：

```
用户输入研究主题
        │
        ▼
① Planner（规划提纲）
   大模型自动生成研究提纲：核心观点 / 行业背景 / 市场规模 / 产业链 / 竞争格局 / 风险 / 结论
        │
        ▼
② Researcher（检索资料）
   自动生成 10 条检索词，去重后搜索相关资料
        │
        ▼
③ Analyst（逐章分析）
   每章自动提炼要点，标注引用来源 [1, 2, 3...]
        │
        ▼
④ Debate（多空辩论）
   多方 vs 空方对抗分析，双方各 3-5 个论点 + 两轮互相反驳
        │
        ▼
⑤ Writer（撰写报告）
   自动写成完整报告
        │
        ▼
⑥ Reviewer（审校修订）
   自动审校：结构完整性 / 引用区间合法性 / 引用覆盖率（非阻断建议）/
             逻辑一致性（LLM）/ 引用溯源提示（非阻断）
   引用覆盖率偏低时打回重写（自动生成章节不计入覆盖率）
        │
        ▼
   输出最终报告（结尾附「🛡️ 反幻觉总览」，如实标注哪些检查执行过、哪些未启用）
```

> ⚠️ 主题研报没有标的公司，构建不了 `FactBase`，因此**不做事实库式的数字交叉校验**。
> 但它有自己的数字级防线——**引用溯源校验**：正文中的财务数字必须能在其引用的检索资料里找到
> （覆盖率与"疑似对不上"的数字会写进「反幻觉总览」；检索结果没有正文时如实显示"未执行"）。
> 需要事实库级校验（差异比对 + 无来源数字 + 覆盖率）请用 `brief`（公司速览）或 `announce`（公告提炼）。

**为什么要这么设计？**  
因为一次性让大模型写完整报告会「顾头不顾尾」，数字容易错、逻辑容易乱。分成 6 个阶段，每个阶段只做一件事，质量更高。

## 🔌 接口与集成详解

### MCP Server（Model Context Protocol）

**什么是 MCP？**  
Anthropic 推出的开放协议（类似 AI 界的 USB-C），用于标准化 LLM 与外部工具/数据源的连接。

**怎么用？**

本项目提供**两种接入方式**，推荐 Claude Desktop 用 stdio：

**方式一：stdio（推荐，Claude Desktop / Cursor 通用）**

在 `claude_desktop_config.json`（Claude Desktop）里配置：

```json
{
  "mcpServers": {
    "research-report-agent": {
      "command": "python",
      "args": ["/绝对路径/research-report-agent/mcp_server.py"]
    }
  }
}
```

stdio 入口 `mcp_server.py` 从 stdin 读 JSON-RPC、把响应写到 stdout，日志走 stderr（不污染协议流）。
自测：

```bash
printf '%s\n' '{"jsonrpc":"2.0","id":1,"method":"tools/list"}' | python mcp_server.py
```

**方式二：HTTP（本机联调方便）**

启动 `python main.py serve` 后，`POST /mcp` 是**裸 JSON-RPC over HTTP**（不是完整的 Streamable HTTP，
不含 session/SSE），适合 curl 与自建客户端：

```bash
curl -s -X POST http://localhost:8000/mcp -H 'Content-Type: application/json' \
  -d '{"jsonrpc":"2.0","id":1,"method":"initialize","params":{"protocolVersion":"2024-11-05","capabilities":{},"clientInfo":{"name":"curl","version":"1"}}}'
```

**可用工具：**

| 工具 | 参数 | 说明 |
|---|---|---|
| `get_stock_brief` | `symbol`（必填） | 公司投研速览（含反幻觉校验） |
| `verify_numbers` | `text`、`symbol`（均必填） | 数字反幻觉校验（symbol 用于加载事实库） |
| `search_web` | `query`（必填）、`max_results`（可选） | 网页检索（离线自动回退 mock） |
| `generate_stock_report` | `topic`（必填）、`deep`（可选） | 生成完整研报 |

服务端实现了 MCP 握手所需的 `initialize`、`notifications/initialized`（不回响应）、`ping`、`tools/list`、`tools/call`。

## 💡 最佳实践

### 怎么用效果最好？

1. **配多个数据源**：在 `config.json` 里写 `data_sources: ["akshare","sina_http","tencent_http"]`，启用容灾与财务口径交叉验证
2. **跑多份报告后看 stats**：跑 5-10 份不同公司的报告，然后用 `python main.py stats` 看看你的模型靠不靠谱
3. **选可信度 A 级的报告**：如果可信度是 B/C/D，建议人工复核关键数据；深度研报的可信度是"未评级"，不要当成 A
4. **用 Web 界面**：新手推荐 Web 界面，零命令操作
5. **配每日推送**：配一次之后，每天早上自动收到自选股速览，不用打开任何页面

### 怎么避免幻觉？

1. **选好模型**：不同模型幻觉率不一样，用 `stats` 命令对比哪个模型更靠谱
2. **多看反幻觉总览**：报告结尾有「🛡️ 反幻觉总览」章节，它会如实说明哪些校验真的跑过
3. **多源交叉验证**：配置多个数据源，同一财务指标不一致会被标记出来
4. **关键数据人工复核**：指标词典之外的数字（人数/市占率/研发投入等）不会被自动校验，请自己核对
